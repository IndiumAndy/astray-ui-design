# 阶段 8 · 首版亲手验收

这是试用清单，不是通过记录。请留一份源设计，另开空白项目做三条流程；需要对照时可打开参考布局或[个人库验收样例](../stage-5/个人库验收样例.uidesign)，不要只打开已做好的样例代替从空白搭建。

| 路线 | 在画布上做 | 在内嵌 iPhone 和默认浏览器分别检查 |
| --- | --- | --- |
| 登录页 | 依次拖入邮箱、密码、按钮；对齐并调整间距，配置表单和校验 | 无效邮箱出现字段提示，焦点移到首个错误；合法输入只提交一次，传值与字段键一致 |
| 设置页 | 拆开设置项，配置通知开关即时动作和保存回调；做一张带固定栏的长页 | 开关上报新值；滚动时固定栏仍可用；局部样式与主动更新共享样式的范围正确 |
| 通讯录 | 搭一行联系人及详情页，配置四个列表状态，连好按行导航 | 依次切换就绪、空、加载、失败，再点两位联系人，详情显示各自数据；返回后仍可选下一位 |

完成后：

1. 保存到新位置，用 Finder 移动并重开；核对图片、样式、设备覆盖和页面连线。
2. 把流程存入个人库，另建项目插入两次；修改一个副本并更新模板，核对旧项目不变。
3. 单独导出列表页并接入宿主路由，再导出两页和完整工程。关闭编辑器后分别构建、启动和操作 SwiftUI 与 React/Astryx。
4. 在生成源码里手改一处，再移动画布控件并重导出。先取消，核对原文件未变；再选保留手改或采用新版本，确认宿主文件没有丢失。
5. 允许本机 MCP，让客户端在一次批次里编辑多个控件，确认画布和预览只更新一次。按 ⌘Z 恢复；让客户端用旧修订提交，确认第一版没有被覆盖。再试暂停或关闭内嵌预览时的错误提示。
6. 从空白开始记下第一次需要说明、找不到入口或不能完成的地方，修改后从相同步骤复测。键盘、文字对比、窗口尺寸、错误提示和撤销仍是验收项。

最终在每条用例旁写「通过」或「待修」；亲手试用前保留「待用户试用」。
