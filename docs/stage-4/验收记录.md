# 阶段 4 · 页面连线、表单与宿主数据

2026 年 11 月 18 日。以阶段 1 提交 `4a76f6d` 和工作区中的阶段 2、3 实现为基线。复测环境为 macOS 26.3、Xcode 26.6、iPhone 17 Pro 模拟器（iOS 26.5）、默认 Chrome 和 Ego Lite。

[交互验收样例](交互验收样例.uidesign)含通讯录、设置、关于面板、联系人详情及新建联系人五张画板。Mac 实窗测试使用样例副本。

| 用例 | 实际结果 |
| --- | --- |
| 页面连线与弹层 | Mac 实窗把设置行的连接点拖到「关于通讯录」，检查器显示新目标。⌘Z 后恢复「设置」。⌥L 打开同一个事件设置。实窗拖动设置画板的标题并保存，文件对比确认只有画板坐标变化。iPhone 和 Chrome 都点通了导航、返回、弹出与关闭。 |
| 应用传入字段 | 示例昵称为「小林」。两端独立宿主更新数据后，已打开的设置页显示「宿主昵称」。 |
| 表单校验与回传 | 空提交后显示姓名、密码及邮箱的字段错误，并把焦点放到姓名。每端宿主此时收到 0 次提交。修正三项后各收到 1 次 `saveProfile`，字段为 `email`、`name`、`nickname`、`password`。宿主返回「邮箱已被使用」时，错误出现在邮箱下。 |
| 独立表单与即时动作 | 两端保存签名时只传 `signature`。关闭消息通知触发 `setNotifications`，Web 记录的值为 `false`。Web 输入搜索词「周」后，宿主得到 `searchContacts` 和 `query: "周"`。SwiftUI 的输入绑定复测得到相同动作和值，同值回写只产生一次回调。 |
| 两类列表 | 设置行可以单独编辑并连接页面。联系人列表共用行字段和行高，示例有三条联系人。两个独立宿主换成 20 条记录后，滚动外层页面找到第 20 条，详情显示对应姓名及电话。 |
| 列表状态 | Mac 检查器实际切换了有数据、空数据、加载中和加载失败。两个独立宿主在加载中和失败时都传入了已有记录，两端优先显示状态文字。空列表按钮打开「新建联系人」。修改画布的预览状态后，内嵌 iPhone 和默认 Chrome 自动刷新。 |
| 控件状态 | 两端实测正常、禁用和输入错误。浏览器宿主将「同步联系人」设为处理中，按钮显示活动指示并阻止点按。检查器支持给适用状态填写文字。 |

## 界面复查

- 画布使用现有的蓝白工作台。选中连线加深，弹层用虚线，事件设置同时提供鼠标和键盘入口。
- iPhone 使用原生返回和弹层。Web 使用浏览器历史和原生对话框。字段保留可见标签和就地提示。iPhone 上修复了聚焦空字段时同值回写会提前清除校验错误的问题。Web 校正了列表行高，确认 20 行时列表内容和占位均为 1120 CSS px。
- 两端使用深红和浅红的错误文字。背景为白色或 `#1C2027` 时，对比分别约为 7.4∶1 和 9.1∶1。
